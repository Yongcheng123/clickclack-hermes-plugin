Hermes × ClickClack Workshop

从连接 Bot，到多人协作完成一个项目

阶段一把每个人自己的 Hermes 接入同一个 ClickClack Channel；阶段二让各自的 Bot 自动认领 Mobius Issue、完成独立模块、提交 PR，并由主持人的 Review Agent 集成。

总时长：约 60 分钟 7–8 位参与者 公开 Repo + 三源固定快照 最后更新：2026-07-29

阶段一：把自己的 Hermes 连接到 ClickClack

参与者只需要复制真正的 Prompt。Bot 表单是网页填写参考，不会提供复制按钮。

01检查 Mobius MCP，同时安装 Plugin
02准备 Mobius PAT 和 ClickClack Bot Token
03一次合并全部配置，只重启一次 Gateway
04验证 Mobius，并在 Channel 完成 PONG
开始前需要：自己的 Hermes Studio Web UI、可登录的 GitHub 账号、自己的准确 Mobius 显示名，以及访问 Mobius 和 Hermes Workshop ClickClack 的权限。
关于 Hermes 版本：参与者不需要记版本号，也不需要自己运行 版本检查。能正常对话是第一步；安装还需要当前 Hermes 支持 plugins 和 gateway。下面的 Prompt 会自动检查， 如果缺少这些能力，直接联系主持人换用备用 Studio。
Access 很重要：Hermes 安装时可能请求 Terminal、文件、Git 或网络 Access。看到请求后要立即允许当前会话，否则 Hermes 会停下来等待。 只授权当前 Hermes 完成本次操作。
备用 Hermes Studio：优先使用自己的 Hermes。自己的 Studio 无法登录、无法启动或无法安装 Plugin 时，再联系主持人分配一个备用实例。 同一时间一个实例只给一位参与者使用。

备用 Studio 1 备用 Studio 2 备用 Studio 3 备用 Studio 4

本阶段只重启一次：先检查或补齐 Mobius MCP，再完成 ClickClack Plugin 和 Bot 配置；所有内容合并完成后才重启 Gateway。 不要为 MCP 和 Plugin 分别重启。

步骤 1：检查 Mobius MCP，同时安装 Plugin

  1. 登录 Mobius，在左下角账户区域确认自己的准确显示名。
  2. 登录自己的 Hermes Studio，开启一个新会话。
  3. 替换 Prompt 中的姓名后发给 Hermes；看到 Access 请求立即允许。
  4. Hermes 检查和安装期间，同步进行步骤 2 和步骤 3。
Prompt 1 · 检查 Mobius MCP，并安装 Plugin 
我的 Mobius 用户名：<YOUR_MOBIUS_USER_NAME>

请在当前 Hermes Studio 完成预检查，并安装这个 Platform Plugin：
https://github.com/Yongcheng123/clickclack-hermes-plugin

要求：
1. 只操作当前 Studio；确认当前 Profile、实际 HERMES_HOME，以及存在
   plugins、gateway 和 MCP 能力。不要因为具体版本号暂停。
2. 如果需要 Terminal、文件、Git 或网络 Access，立即向我请求；获批后继续。
3. 如果 hermes 不在 PATH，使用 /opt/hermes/.venv/bin/hermes。
4. 安全检查现有 config.yaml 中是否已经有 mcp_servers.mobius。不要显示任何
   Authorization Header、Token、PAT 或 Secret。
5. 如果 Mobius MCP 已注册，调用一次只读的 list_teams 验证：
   - 调用成功：记录为 CONNECTED；
   - 没有配置、没有工具、401/403 或调用失败：记录为 NEEDS_KEY。
   本步骤不要修改 MCP 配置。
6. Plugin 未安装时运行：
   hermes plugins install Yongcheng123/clickclack-hermes-plugin --no-enable
   已安装时运行：
   hermes plugins update clickclack-hermes
7. 暂时不要启用 Plugin，不要修改 config.yaml，不要重载 MCP，也不要重启
   Gateway；停在 not enabled，等待我把所有配置一次交给你。
8. 安装器创建 Plugin 目录的模板 .env 是正常的，但不要把真实 Token 写进去。
9. 不要覆盖现有模型、MCP、Gateway、Memory 或其他配置。

完成后只报告：
- 我提供的 Mobius 用户名
- Mobius MCP：CONNECTED 或 NEEDS_KEY
- HERMES_HOME 和 Plugin 安装路径
- Plugin 状态
- plugins、gateway、MCP 能力是否可用
- 本轮 Gateway 重启次数必须为 0
预期结果：Plugin 能被 hermes plugins list 发现； not enabled 表示正在等待一次性最终配置，不是报错。记住 Hermes 报告的 Mobius MCP 状态：CONNECTED 或 NEEDS_KEY。

步骤 2：需要时生成 Mobius Personal Access Token

如果 Prompt 1 报告 CONNECTED，跳过生成 Token，最终 Prompt 填 KEEP_EXISTING。如果报告 NEEDS_KEY：

  1. 打开 Mobius → 开发者。
  2. 找到你的访问令牌，名称填写 hermes-workshop。
  3. 点击生成，立即复制只显示一次的 mob_… Token。
  4. 保留自己的准确 Mobius 显示名，阶段二仍会使用同一个名字。
Mobius PAT 只显示一次：不要把真实 mob_… Token 发到 ClickClack、Git、文档或公开群聊。它只粘贴到你自己的 Hermes Studio 私人会话中，并由 Hermes 写入权限为 0600 的 HERMES_HOME/.env。

步骤 3：在 ClickClack 创建自己的 Bot

进入 Workspace settings → Automation → Bots & agents， 点击 Add bot。这部分是网页表单，不是 Prompt，请逐项填写。

步骤 4：一次配置 Mobius MCP、Plugin 和 Gateway

回到刚才同一个 Hermes 会话。确认它已报告 clickclack-hermes not enabled，复制下面 Prompt，替换 Mobius 用户名、Mobius PAT 状态和 ClickClack Bot Token：

  • Mobius 已连接：把 <MOBIUS_PAT_OR_KEEP_EXISTING> 替换为 KEEP_EXISTING。
  • Mobius 未连接：替换为刚生成的完整 mob_… Token。
  • 把 <PASTE_YOUR_CCB_BOT_TOKEN_HERE> 替换为完整 ccb_… Token。
Prompt 2 · 一次配置 Mobius + ClickClack，只重启一次 
请在当前 Hermes Studio 一次完成 Mobius MCP 和 ClickClack Plugin 配置。

只操作当前 Studio。下面的值只授权用于本次 Workshop。不要在回复、工具输出、
日志或 Git 中显示任何 Token。

MY_MOBIUS_USER_NAME: <YOUR_MOBIUS_USER_NAME>
MOBIUS_PAT: <MOBIUS_PAT_OR_KEEP_EXISTING>
CLICKCLACK_BOT_TOKEN: <PASTE_YOUR_CCB_BOT_TOKEN_HERE>

请执行：
1. 确认使用 Prompt 1 找到的同一个 Profile 和 HERMES_HOME。
2. 备份现有 config.yaml；后续只做合并，保留所有现有模型、MCP、Gateway、
   Memory 和其他配置。
3. 把 CLICKCLACK_BOT_TOKEN 安全写入 HERMES_HOME/.env。
   - 如果 MOBIUS_PAT 是完整的 mob_… Token，也写为 MOBIUS_PAT；
   - 如果值是 KEEP_EXISTING，保留当前可用的 Mobius Header 和凭证，不要
     把 KEEP_EXISTING 写进任何文件。
   将 .env 权限设为 0600，不要写入 Plugin 目录、日志或 Git。
4. 如果 Mobius 状态是 NEEDS_KEY，合并以下 MCP 配置。Header 必须引用环境
   变量，不要把真实 PAT 明文写入 config.yaml：

mcp_servers:
  mobius:
    url: "https://mobius.feedmob.com/api/mcp"
    headers:
      Authorization: "Bearer ${MOBIUS_PAT}"
    enabled: true
    connect_timeout: 60
    timeout: 120

   如果 Mobius 状态是 CONNECTED 且 MOBIUS_PAT 为 KEEP_EXISTING，保留现有
   mcp_servers.mobius，不要创建重复条目。
5. 合并以下 ClickClack 配置：

plugins:
  enabled:
    - clickclack-hermes

gateway:
  platforms:
    clickclack:
      enabled: true
      home_channel:
        chat_id: "channel:chn_01kynt5edyr9t13dd5nxws7nvf"
        name: "general"
      extra:
        base_url: "https://clickclack-ken-team.feedmob.it.com"
        workspace_id: "wsp_01kynt5edyr9t13dd5nxf3c0gx"
        default_channel_id: "chn_01kynt5edyr9t13dd5nxws7nvf"
        allowed_channel_ids:
          - "chn_01kynt5edyr9t13dd5nxws7nvf"
        allowed_user_ids: []
        allow_all_users: false
        require_mention: true
        allow_dms: false
        thread_mode: "always"
        skip_history_on_first_start: true

6. 启用 clickclack-hermes，并运行 Plugin 自带 doctor。
7. 在重启前检查 YAML 可解析、Plugin 配置完整、Mobius MCP 只有一个条目，
   且两个 Secret 都未出现在 config.yaml 或输出中。
8. 现在才重启当前 Hermes Gateway 一次；不要重启其他服务器或容器，也不要
   在此前单独重载或重启 MCP。
9. Gateway 恢复后：
   - 验证 ClickClack 显示 connected；
   - 验证 Mobius MCP 已注册工具；
   - 调用一次 Mobius list_teams，只读确认能看到“周四练习（THU）”；
   - 不要在 Mobius 创建、修改或评论 Issue。
10. 最后只报告：
   - Mobius 用户名
   - Mobius MCP 是否 connected，list_teams 是否成功
   - Plugin 是否 enabled
   - Doctor 是否全部 PASS
   - Gateway 是否显示 ClickClack connected
   - 本次 Gateway 重启次数（必须为 1）
   - 下一步应使用的 Bot handle

如果需要新的 Access，请向我请求，获批后继续。

步骤 5：在 ClickClack 做 PONG 测试

回到 #general，手动发送： @<YOUR_BOT_HANDLE> 请只回复 PONG。 因为启用了 require_mention，必须准确 @ 自己的 Bot。

阶段二：Bot 自动认领 Issue 并完成 PR

参与者不需要手动挑选 Issue、手动分配、手动写 PLAN/BLOCKED/READY。 使用阶段一确认并连接 MCP 时填写的同一个 Mobius 用户名，把一个 Prompt 发给自己的 Hermes。当前基线已经包含三张 Chime 数据源、345 条小时记录 和完整 18 项指标；参与者只完成各自隔离的 Feature。

01Bot 在 THU-1 下随机选择未分配 Issue
02自动分配、In Progress、评论 TAKEN
03开发、测试、同步 Mobius、提交 PR
04Review Agent 验收并合入 integration
开始前：阶段一 PONG 已通过；Hermes 已获得 Mobius 和 GitHub 访问权限。遇到 Access 请求要及时允许，否则 Bot 会停下来等待。
当前项目基线：Repo 已内置 2026-07-24 至 2026-07-28 的 三张 Chime FeedTV 固定快照，共 345 条小时记录、18 项指标。Agent_B 在 7 月 24 日只有 9/24 小时，这是原始快照中的真实缺口。Workshop 不连接 实时 API，也不需要 Beeswax MCP 或生产凭据。

参与者 Prompt · 自动认领、开发、同步和提交 
你是我在 Hourly Dashboard Workshop 中的开发 Agent。

我的 Mobius 用户名：<YOUR_MOBIUS_USER_NAME>
Mobius 团队：周四练习（THU）
父 Issue：THU-1
代码仓库：https://github.com/Yongcheng123/hourly-dashboard-practice
参与者 PR 的 Base 分支：integration/workshop

请替我完整执行以下流程：

1. 先确认你可以读取和更新 Mobius，并且可以使用 GitHub。如果缺少权限，
   立即向我申请 Access；我批准后继续执行，不要静默停止。

2. 读取 THU-1 及其所有直接子 Issue。可认领的 Issue 必须同时满足：
   - 没有 Assignee；
   - 状态为 Todo 或 Backlog；
   - 评论中没有其他参与者留下的 TAKEN。

3. 在认领前立即刷新一次子 Issue 列表，从符合条件的 Issue 中随机选择一个。
   把它分配给我上面提供的准确 Mobius 用户名，将状态改为 In Progress，
   并添加以下评论：
   TAKEN
   Owner: <YOUR_MOBIUS_USER_NAME>
   Hermes bot: current bot
   Started: current time

4. 重新读取该 Issue，确认 Assignee 是我且状态为 In Progress。如果其他参与者
   抢先认领，不要覆盖对方；改选另一个可认领 Issue 并重复上述步骤。如果已经
   没有可认领的 Issue，告诉我并停止，不要修改代码。

5. 阅读已认领 Issue 的完整描述和 Acceptance Criteria。由你直接在该 Issue
   添加 PLAN 评论，写明允许修改的文件、实现方案和风险；不要让我手动复制
   或填写 PLAN 模板。

6. Fork 或 Clone 公开仓库，以 upstream/integration/workshop 为起点创建：
   feat/<CLAIMED_ISSUE_ID>-<SHORT_NAME>

7. 只修改 Issue 明确允许的文件。除非 Issue 明确允许，否则不要修改
   DashboardShell、RawHourlyTable、SourceComparisonTable、globals.css、
   chime 数据文件、共享 data/types、package.json 或 lockfile。
   不要使用生产环境凭证，也不要添加仓库快照之外的真实 Campaign 数据。

8. 使用仓库现有的三张 Chime 固定快照和视觉风格完成 Acceptance Criteria。
   不连接实时 API，不伪造 Agent_B 缺失小时，并保持 Dashboard 响应式和可访问。

9. 如果遇到阻塞，由你直接在已认领的 Mobius Issue 添加 BLOCKED 评论，说明
   阻塞原因以及需要的 Access 或决策，然后再向我提问；不要让我手动写评论。

10. 运行 npm run lint 和 npm test，并在允许修改的范围内修复失败项。

11. Commit 并 Push Feature Branch，然后向以下 Base 创建 Pull Request：
    Yongcheng123/hourly-dashboard-practice:integration/workshop
    PR 标题必须包含已认领的 Mobius Issue ID。

12. 由你直接在已认领的 Mobius Issue 添加 READY 评论，包含 Branch、PR URL、
    修改文件、Lint 结果、Test 结果和风险，并把 Issue 改为 In Review；
    不要让我手动复制或填写 READY 模板。

13. 最后只向我报告：认领的 Issue ID/标题、Branch、PR URL、测试结果，以及
    需要人工检查的事项。绝对不要自行合并 PR。
参与者完成标准：Bot 已自动认领一个 Issue；Mobius 显示 In Review 和 READY 评论；GitHub PR 的 Base 是 integration/workshop。

主持人：让 Review Agent 集成

等参与者 PR 到齐后，给主持人的 Agent GitHub 和 Mobius 权限，再发送下面 Prompt。Review Agent 会更新 Mobius、逐个合并到 integration，并创建最终 PR。

主持人 Review Agent Prompt 
你是 Hourly Dashboard Workshop 的集成与 Review Agent。

代码仓库：https://github.com/Yongcheng123/hourly-dashboard-practice
Mobius 团队：周四练习（THU）

参与者 PR 的 Base 分支：integration/workshop
最终分支：main
